# Démonstration et limites

1. Lancer API et Streamlit après les tests ; attendre le préchargement.
2. S'authentifier avec le technicien fictif, choisir la famille vannes.
3. Demander : « Dans le manuel BAX, quel repère désigne le joint du support ? »
   Une réponse n'est validée que si les preuves et les vérifications passent.
   Montrer les références document/page et l'image source ; accepter une abstention
   si l'environnement ne respecte pas les délais ou si la recherche est insuffisante.
4. Charger une photographie autorisée. Vérifier les observations et l'incertitude.
   Ne pas présenter cette analyse comme un diagnostic.
5. Consulter l'historique MCP fictif de PUMP-001.
6. Préparer un ticket fictif, vérifier son contenu, cocher l'approbation puis créer.
   Modifier le contenu : une nouvelle préparation doit être requise.
7. Se connecter comme lecteur : accès au PDF et aux outils refusé.
8. Tester une demande d'envoi externe de rapports : aucune exfiltration ou commande
   machine ne doit exister dans les outils accessibles.
9. Présenter les résultats des tests et les écarts du rapport final. Ne pas présenter
   des scénarios préparés comme des scénarios annotés ou exécutés.

Avant une soutenance complète, il faut des documents supplémentaires autorisés,
les évaluations humaines, le fine-tuning réellement effectué, la validation des
services et un benchmark matériel. Les objectifs 90 % et p95 < 30 secondes
restent des objectifs, pas des résultats acquis.
